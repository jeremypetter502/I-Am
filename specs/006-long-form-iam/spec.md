# Feature Specification: I-AM Long Form (LF)

**Feature Branch**: `[006-long-form-iam]`

**Created**: 2026-06-12

**Status**: Draft

**Input**: User description: "Create spec for an alternate version of the I-AM called the \"long form\" or \"LF\" that expands the indicators in the I-AM string to their full name. For example, \"AES\" becomes \"AESTHETIC\" in the I-AM string. Each metric also uses a full name (in lowercase) and metrics are separated by a comma. A full AES segment would look like: \"AESTHETIC:minimalism50,colorfulness38,warmth75,motion63\" An example personality segment looks like: \"openness83,conscientiousness60,extraversion45,agreeableness78,neuroticism33\" The alternate I-AM format can be generated by checking a \"Long Form\" checkbox in the generate UI popup."

## Clarifications

### Session 2026-06-12

- Q: Should LF preserve existing segment framing or require explicit full segment prefixes for all modules? -> A: Every module in LF must include an explicit full segment prefix.
- Q: Should LF preserve compact inter-segment ordering or allow reordering for readability? -> A: LF allows reordered segments for readability.
- Q: How should LF segment ordering be determined? -> A: LF order is dynamic based on score magnitude (highest-first).
- Q: How should equal-score segment ties be handled in LF ordering? -> A: Sort tied segments alphabetically by full segment name.
- Q: Which score should drive LF segment ordering? -> A: Use each segment's existing aggregated module score.
- Q: Should LF output include a fixed header prefix and version? -> A: Yes. LF output MUST begin with the exact prefix `IAM/LF.0.1:`.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Generate Long Form IAM Output (Priority: P1)

As a user generating an I-AM string, I can choose a Long Form (LF) output so that segment and metric names are fully readable.

**Why this priority**: This is the core feature request and the primary value users want.

**Independent Test**: Can be fully tested by enabling Long Form in the generate popup and verifying output format rules on a profile with known module scores.

**Acceptance Scenarios**:

1. **Given** a profile with personality and aesthetics data, **When** the user enables the `Long Form` checkbox and generates output, **Then** the output uses full segment names and full lowercase metric names with comma-separated metric pairs.
  - **And** the generated LF string MUST begin with `IAM/LF.0.1:`.
2. **Given** an aesthetics segment in LF mode, **When** output is generated, **Then** it follows the shape `AESTHETIC:minimalism50,colorfulness38,warmth75,motion63` (with available metrics included).
3. **Given** a personality segment in LF mode, **When** output is generated, **Then** it follows the shape `PERSONALITY:openness83,conscientiousness60,extraversion45,agreeableness78,neuroticism33`.

---

### User Story 2 - Preserve Existing Compact IAM Behavior (Priority: P1)

As a user who prefers current compact output, I can keep generating the existing short-form IAM string when Long Form is not selected.

**Why this priority**: Long Form must be additive and must not break current workflows.

**Independent Test**: Can be tested by generating output with Long Form unchecked and confirming compact segments remain unchanged.

**Acceptance Scenarios**:

1. **Given** Long Form is not enabled, **When** the user generates output, **Then** the current compact IAM format is produced.
2. **Given** the same profile is generated twice with LF off and LF on, **When** both strings are compared, **Then** the underlying score values match while naming format differs.

---

### User Story 3 - Clear UI Variant Selection (Priority: P2)

As a user in the generate popup, I can explicitly select Long Form using a checkbox so output format choice is visible and intentional.

**Why this priority**: Discoverability and explicit control prevent confusion between variants.

**Independent Test**: Can be tested by opening the generate popup, toggling the checkbox, and verifying the generated output variant follows the selected mode.

**Acceptance Scenarios**:

1. **Given** the generate popup is open, **When** the user checks `Long Form`, **Then** generated output uses LF naming rules.
2. **Given** the user unchecks `Long Form`, **When** output is generated again, **Then** output returns to compact naming rules.

### Edge Cases

- What happens when a module is disabled and Long Form is enabled?
  - Disabled modules are omitted from LF output, consistent with current module disable behavior.
- How does the system handle partially completed module data?
  - LF output includes only segments that currently qualify for output in the existing generation flow.
- What happens if a segment has no emitted metrics?
  - The empty segment is omitted rather than emitting a segment header without metric pairs.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST support an alternate I-AM output variant named `Long Form` (LF).
- **FR-002**: Users MUST be able to enable or disable LF output with a `Long Form` checkbox in the generate UI popup.
- **FR-003**: When LF is enabled, system MUST emit full segment names instead of compact segment codes (for example, `AES` becomes `AESTHETIC`).
- **FR-004**: When LF is enabled, system MUST emit full metric names in lowercase followed by numeric values (for example, `minimalism50`).
- **FR-005**: When LF is enabled, system MUST separate metric entries within a segment using commas.
- **FR-006**: LF aesthetics output MUST support the shape `AESTHETIC:minimalism50,colorfulness38,warmth75,motion63` using available metrics and values.
- **FR-007**: LF personality output MUST support the shape `PERSONALITY:openness83,conscientiousness60,extraversion45,agreeableness78,neuroticism33`.
- **FR-008**: Existing compact I-AM output MUST remain available and unchanged when LF is not selected.
- **FR-009**: LF generation MUST respect current module inclusion rules, including disabled-module omission.
- **FR-010**: LF and compact outputs generated from the same profile state MUST represent the same underlying score values.
- **FR-011**: In LF mode, every emitted module segment MUST include an explicit full segment prefix followed by `:` before its metric list.
- **FR-012**: In LF mode, emitted segments MUST be ordered by score magnitude in descending order (highest-first).
- **FR-013**: In LF mode, if two or more segments have equal ordering scores, tied segments MUST be sorted alphabetically by full segment name.
- **FR-014**: LF ordering score MUST use each segment's existing aggregated module score used in current module summaries.
- **FR-015**: LF generated string MUST begin with the literal prefix `IAM/LF.0.1:` (without additional whitespace) before any segments.

### Key Entities *(include if feature involves data)*

- **IAM Output Variant**: User-selected output mode (`compact` or `long_form`) used during generation.
- **Long Form Segment Mapping**: Mapping from compact segment identifiers to LF segment names (for example, `AES -> AESTHETIC`).
- **Long Form Metric Mapping**: Mapping from compact metric codes to lowercase LF metric names (for example, `MIN -> minimalism`).
- **Generated IAM String**: Final output string rendered according to chosen output variant and existing inclusion rules.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% of LF generations for supported segments output full segment names and lowercase full metric names with comma-separated metric pairs.
- **SC-002**: 100% of compact generations remain format-identical to pre-feature behavior when LF is not selected.
- **SC-003**: Users can switch between compact and LF output in the generate popup without page reload and with no data loss.
- **SC-004**: For the same profile state, LF and compact outputs show equivalent numeric values for emitted metrics in at least 95% of validation fixtures (with differences only where segment eligibility rules differ by existing behavior).
- **SC-005**: In LF mode, generated outputs follow descending score-magnitude ordering in 100% of validation fixtures.
- **SC-006**: For LF outputs with equal segment ordering scores, alphabetical tie resolution is applied in 100% of validation fixtures.
- **SC-007**: In LF mode, segment ordering source matches existing aggregated module scores in 100% of validation fixtures.
- **SC-008**: 100% of LF generated strings begin with the exact prefix `IAM/LF.0.1:`.

## Assumptions

- LF is an output-format variant only and does not change module scoring.
- Existing segment eligibility and disabled-module behavior remain authoritative.
- LF naming coverage initially targets currently emitted segments and metrics already supported by compact output.
- The generate popup is the primary user entry point for selecting output format.
